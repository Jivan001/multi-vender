SIP PROJECT WRITE-UP

Multi-Vendor E-Commerce Platform

Project type: MCA SIP front-end prototype

Important: This is an educational HTML, CSS and JavaScript demonstration, not a deployable commercial marketplace.

Abstract

CampusCart demonstrates the customer and vendor-facing journey of a multi-vendor online marketplace. Users can discover products, filter the catalogue, maintain a cart, place a simulated order, track its progress and view an invoice. Vendors can add products to a browser-stored catalogue.

Objectives

  • Present products from multiple vendors in one interface.
  • Demonstrate search, filters, cart and order workflow.
  • Show a simple vendor catalogue operation.
  • Use responsive, accessible front-end design.

Scope

The prototype covers the visible flow: catalogue, vendor dashboard, cart, checkout, order tracking and invoice. Data persists with localStorage on one device.

Technologies

HTML5 for structure, CSS3 for responsive styling and vanilla JavaScript for interactions and localStorage persistence.

Modules

  1. Catalogue: search, category/vendor filter and sorting.
  2. Cart: quantity controls and price calculation.
  3. Checkout: address form and simulated payment choice.
  4. Orders: status timeline and invoice modal.
  5. Vendor desk: browser-only product entry and totals.

Workflow

Browse → filter/search → add items → open cart → simulated checkout → order confirmation → order tracking → invoice. The vendor form updates the catalogue in the same browser.

Testing

Manual functional tests cover adding/removing cart items, quantity and total calculation, filters, form validation, checkout creation, order tracking, invoice display, reset and responsive layout.

Limitations

No real login, role control, inventory control, backend API, database, payment processing, shipment integration or secure invoice storage exists. localStorage is editable and unsuitable for sensitive data.

Conclusion

The project is a clear, explainable proof of concept for a multi-vendor marketplace interface. A real implementation requires a backend, authentication, validation, secure payment provider and database.

Run instructions

Open index.html in a modern browser. No installation, server or internet connection is required. Use Reset all demo data to restore the initial catalogue.
